# CLEAN_UP_VERIFIED — Migration Plan

This documents every place `verified` (or `SWE-bench_Verified`) is referenced in `./experiment/`, the
coupling mechanism, and what would need to change to support a different SWE-bench subset (or a
non-SWE-bench dataset with the same column schema).

---

## 1. The Coupling Mechanism

There is **one** key that propagates everywhere: the string `"verified"`, which resolves to the HuggingFace dataset name `princeton-nlp/SWE-bench_Verified` via a `DATASETS` dict in two places:

| Location | Dict |
|----------|------|
| `analysis/evaluate_patches.py:67-71` | `{"verified": "princeton-nlp/SWE-bench_Verified", "lite": "princeton-nlp/SWE-bench_Lite", "test": "princeton-nlp/SWE-bench"}` |
| `analysis/correct_submissions.py:37` | imports from `evaluate_patches.py` (single source of truth) |

The command-line default `"verified"` is set in three entry points, each reading `DATASETS`:

| Script | Flag | Line |
|--------|------|------|
| `run_experiment.py` | `--subset` | 299 |
| `analysis/evaluate_patches.py` | `--subset` | 195 |
| `analysis/correct_submissions.py` | `--subset` | 123 |

`run_one.py:197` passes `--subset` through to `mini-extra swebench-single`, which loads the dataset.

**To add a new subset** (e.g. `"pro"`):
1. Add the entry to `DATASETS` in `evaluate_patches.py` (one line).
2. Add the choice to `--subset` in `run_experiment.py` (one word in the `choices` list).
3. The `correct_submissions.py` and `evaluate_patches.py` `--subset` args derive their choices from `list(DATASETS)` automatically — no change needed there.

## 2. Hardcoded / Pinned References

### `scripts/build_pool.py`

- **Line 42:** `DATASET = "princeton-nlp/SWE-bench_Verified"` — hardcoded, not using the `DATASETS` dict.
- **Line 43:** `DATASET_REVISION = "c104f840cc67f8b6eec6f759ebc8b2693d585d4a"` — pinned HF revision for reproducibility.
- **Line 84:** `default=paths.EXPERIMENT_DIR / "verified_docker_images.txt"` — the output filename is named `verified_*`.

For a new subset, `build_pool.py` needs the dataset name and revision updated (or parameterized). The output filename should follow the new subset name.

### `scripts/sample_pool.py`, `sample_pool_by_nfiles.py`, `sample_pool_large_biased.py`

- All print header comments like `# N balanced SWE-bench Verified instances` — cosmetic only, not functional.
- The actual instance IDs come from whichever pool file is piped in, not from `verified` hardcoding.

### Minisweagent base config (third-party, in `.venv/`)

- **`.venv/lib/python3.12/site-packages/minisweagent/config/benchmarks/swebench.yaml`** — the `mini-extra swebench-single` command loads from `princeton-nlp/SWE-bench_Verified` by **internal default** (not something we pass). Our `--subset` flag overrides this, so it works for `lite`/`test` today.
- If a new subset isn't supported by the version of minisweagent we're pinned to, this would need a minisweagent upgrade or a local fork.

## 3. File Naming Conventions

Files prefixed with `verified_` exist for discoverability but are not referenced programmatically by name (all are passed as CLI arguments):

| File | Purpose |
|------|---------|
| `verified_instance_ids.txt` | Primary 5-instance balanced set (seed=1200) |
| `verified_instance_ids-backup.txt` | Backup copy |
| `n18_verified_instance_ids.txt` | 18-instance set (seed=126660) |
| `verified_docker_images.txt` | 70-instance pool with DockerHub image names |

These don't need to be renamed for a migration — new instance files would be generated for the new subset anyway. The old files remain valid for reproducing prior results.

## 5. Log Files and Trajectories

Every `.log` file under `logs/` contains the line:

```
minisweagent: INFO: Loading dataset from princeton-nlp/SWE-Bench_Verified, split test
```

This is generated by minisweagent at runtime and is historical/immutable — no action needed. New runs against a different subset would emit a different dataset name automatically.

## 6. Migration Checklist (for adding a new subset `X`)

- [ ] Add `"X": "princeton-nlp/SWE-bench_X"` to `DATASETS` in `analysis/evaluate_patches.py:67`
- [ ] Add `"X"` to `choices=["lite", "verified", "test", "X"]` in `run_experiment.py:299`
- [ ] Update `scripts/build_pool.py` `DATASET` + `DATASET_REVISION` (or parameterize via `--subset`)
- [ ] Verify minisweagent's `swebench.yaml` (or equivalent) supports the new subset
- [ ] Build new pool file(s) for the new subset
- [ ] Generate new instance ID files from the new pool
- [ ] Pull Docker images for new instances
- [ ] Index new instances with `pre_index.py` / `index_instance.sh`
- [ ] Update docs if this is a full replacement; otherwise add new docs for the new subset path
- [ ] Consider whether `--subset` in `run_one.py:197` passes through correctly (it should, as long as minisweagent supports it)

---

## 7. What Does NOT Need to Change

- **Prompt configs** (`config/*.yaml`, `config/*.smconfig`): These are instance-agnostic — they template in `{{task}}` and instructions. No benchmark name appears in any prompt.
- **Analysis tooling** (`analysis/report_*.py`, `analysis/compare_*.py`, `analysis/extract_*.py`): These operate on trajectory CSVs and don't reference the benchmark name.
- **`pre_index.py`**, **`index_instance.sh`**: These operate on instance IDs + Docker images; the benchmark name isn't embedded (only the instance IDs matter).
- **`compare.sh`**: Only shows example commands; non-functional.

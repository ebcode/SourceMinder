## Issues Encountered

### Deleted Files Never Reached Database Cleanup

- **Symptom:** Symbols from deleted files remained in `code-index.db` after removing a watched file.
- **Root Cause:** `shared/indexer_main.c` only called `db_delete_by_file(...)` after `parser_parse(...)` succeeded, but every parser fails immediately when the file no longer exists.
- **Fix:** Added path-based deletion using `get_relative_path(...)` and handled `FILE_EVENT_DELETED` without attempting to parse the missing file.
- **Regression Risk:** `LOW`
- **Follow-Up:** Add a shared manual test script or fixture set for delete/rename/create watcher behavior across platforms.

### Recursive Watch Coverage Drifted After Tree Changes

- **Symptom:** New directories and their files were not reliably watched after startup, especially on macOS/BSD where only existing files were watched.
- **Root Cause:** Linux and Windows built the recursive watch set only once at startup; the BSD backend watched files only and had no mechanism to discover new files later.
- **Fix:** Added recursive re-watch behavior for Linux and Windows, and reworked the BSD backend to track watched roots, watch directories, rescan on structural changes, add newly discovered files, and prune vanished watches.
- **Regression Risk:** `MEDIUM`
- **Follow-Up:** Verify watcher behavior on real macOS and Windows/MSYS2 environments rather than relying on Linux-only compilation.

### Daemon Smoke Test Was Initially Filtered Out

- **Symptom:** The new delete smoke test failed even though the Linux watcher emitted delete events.
- **Root Cause:** The test fixture was placed under `tmp/`, and `c/config/ignore_files.txt` excludes `tmp`, so the watch loop skipped the event.
- **Fix:** Moved the test fixture and query scratch output into `scratch/`, which is not excluded by the C indexer config.
- **Regression Risk:** `LOW`
- **Follow-Up:** Document test fixture path constraints for language-specific ignore rules.

## Residual Risks / Not Verified

- The watcher backend changes were only executed on Linux in this session; macOS/BSD and Windows/MSYS2 behavior was validated by code inspection and successful compilation paths, not by runtime testing.
- One-shot directory mode still does not remove stale rows for files that disappeared between runs; this remains intentionally deferred because automatic pruning could be surprising for moved on-disk indexes.

---

## Notes / Design Decisions

- The fix was kept in the shared orchestration layer instead of pushing delete-path logic into every language parser. This preserves the parser contract and keeps missing-file handling centralized.
- Broad "delete all indexed files not found in the current scan" behavior was intentionally not implemented after considering the user case where an existing index file is moved into a new directory and expanded there.

## Freeform Thoughts

The main bug was simpler than it first appeared: delete events already existed, but the shared daemon flow tied row deletion to successful reparsing. The cross-platform complexity showed up immediately after that, though, because recursive watching was only partially maintained after startup. The macOS/BSD backend in particular benefited from being reframed around root rescans rather than trying to force a purely file-watched model to behave like a directory watcher.

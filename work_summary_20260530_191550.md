## Issues Encountered

### TOC Import Counts Disagreed

- **Symptom:** `Result breakdown` showed `IMP (37)` while the rendered import section showed `IMPORTS (21)`.
- **Root Cause:** The summary counted raw indexed import rows, while `print_imports()` deduplicated import symbols. Repeated X-macro includes of `shared/column_schema.def` inflated the raw count.
- **Fix:** Changed TOC summary counting so `IMP` uses `COUNT(DISTINCT full_symbol)`, matching rendered unique imports.
- **Regression Risk:** `LOW`
- **Follow-Up:** Consider documenting that TOC import counts are unique symbols, while normal `-i imp` output shows raw rows.

### TOC Debug Flag Was Not Propagated

- **Symptom:** `--debug` worked in normal query mode but did not print SQL for `--toc`.
- **Root Cause:** `TocConfig` had no debug field, so `shared/toc.c` could not know that SQL debugging was requested.
- **Fix:** Added `debug` to `TocConfig`, passed it from `query-index.c`, and printed TOC count/main SQL queries when enabled.
- **Regression Risk:** `LOW`
- **Follow-Up:** SQL debug output is still long single-line text and could be made more readable.

### Type Definitions Inside Header Guards Were Missing

- **Symptom:** `./qi TocConfig --def -e` returned no results, even though `TocConfig` is defined in `shared/toc.h`.
- **Root Cause:** The C parser handled `preproc_ifdef` / `preproc_if` nodes and returned without traversing their children, so declarations inside include guards were skipped.
- **Fix:** After handling preprocessor conditional nodes, the C parser now processes their children before returning.
- **Regression Risk:** `MEDIUM`
- **Follow-Up:** Add a regression fixture for typedefs inside C header guards.

### Function-Like Macros Appeared As Functions

- **Symptom:** TOC `FUNCTIONS` was noisy with `COLUMN`, `INT_COLUMN`, and `TOC_APPEND` entries.
- **Root Cause:** C function-like preprocessor definitions were explicitly indexed as `CONTEXT_FUNCTION` with `clue=macro`; object-like macros were indexed as `CONTEXT_VARIABLE`.
- **Fix:** Added `CONTEXT_MACRO`, indexed C macros as `MACRO`, and added a separate TOC `MACROS` section.
- **Regression Risk:** `MEDIUM`
- **Follow-Up:** Existing databases and scripts expecting macro definitions under `FUNC clue=macro` or `VAR clue=macro` need reindexing and query updates.

### TOC Limit Semantics Were Structurally Confusing

- **Symptom:** `--toc --limit` produced partial TOCs where hidden file rows and imports consumed slots before useful sections appeared.
- **Root Cause:** `--limit` is row-oriented, while `--toc` is structural; the two modes do not compose cleanly.
- **Fix:** Centralized TOC validation now rejects unsupported flags, including `--limit` and `--limit-per-file`, and prints a supported-flag hint.
- **Regression Risk:** `LOW`
- **Follow-Up:** Add CLI UX tests for `--toc` unsupported flags.

## Notes / Design Decisions

- Kept TOC validation policy in `shared/toc.c`, while `query-index.c` only collects unsupported flag names. This keeps TOC-specific UX centralized without passing all query internals into TOC.
- Chose `CONTEXT_MACRO` over `FUNC clue=macro` because macro-ness is a primary symbol classification, not an auxiliary hint.
- Kept Rust macro invocations as `CALL type=macro` because invocation behavior is call-like, while definitions are macro declarations.
- Removed the `mac` alias because repository convention only shortens context names longer than five characters.
- Used `object-like` instead of `object` for C object-like macros to avoid confusion with structs or OOP objects.

## Freeform Thoughts

The highest-value theme was making the CLI more honest: do not show internal SQL patterns as user-facing file filters, do not call macros functions, do not let `--toc --limit` produce structurally misleading partial output, and do not let unsupported flags appear to work when TOC ignores them.

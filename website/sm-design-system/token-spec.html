Semantic Mapping

Product Roles

The semantic layer is still the contract. Brand hues can evolve later without rewriting component intent.

Surface + Type

--color-bg, --color-surface, --color-fg, and --color-fg-2 now resolve to dark blueprint defaults.

Info / Primary

--color-primary and --color-info both map to Airlock cyan for consistent action and product emphasis.

Warning / Highlight

--color-warning and --color-highlight inherit Airlock amber rather than a separate marketing amber family.

Success

--color-success now points at --pass-700, with --pass-400 available as the lighter companion shade.

Danger

--color-danger now points at --fail-700, with --fail-400 available for the lighter companion red.

Reference

Key Token Decisions

This is the contract to build components against before the component gallery starts.

Area Decision Why
Color system PluginTeam semantics + Airlock hues Keeps component APIs stable while shifting the visual language toward the stronger blueprint palette.
Spacing Airlock full scale through --sp-24 Restores the 24px rhythm and removes the need for improvised spacing values.
Typography Geist + Geist Mono Preserves the best existing font foundation while dropping the more stylistically divergent families from SourceMinder.
Labels 16/24 mono uppercase This is one of the clearest Airlock signatures and should become shared interface chrome.
Modes default dark + data-mode="paper" Both modes are tokenized, so future components can adapt without duplicate style sheets.

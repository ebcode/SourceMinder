Component Gallery

This page starts locking the shared interaction and content patterns into reusable components. The first pass covers buttons, cards, links, and tables using the same blueprint and vellum language established in the token spec.

Buttons

Light BG Buttons

Buttons should read as blueprint controls first: mono labels, strong borders, and a clear hierarchy between filled and framed actions.

stationary shadow - larger offset, ink color
Primary

Offset-shadow control

Every button now shares the same settling motion: 2px offset at rest, 1px on hover, zero on active. That keeps the family coherent across variants.

Variants

Clear hierarchy

Primary uses cyan, secondary uses vellum, ghost stays quiet, danger shifts to breach red, and the pixel CTA gets the larger signature offset.

Buttons

Dark BG Buttons

Cards

Framed Content Blocks

Links

Navigational Language

Links should stay precise and understated. The accent color is meaningful, so link styling should never feel ornamental.

Default inline link Quiet mono link docs/spec.md
Usage

Choose the quieter link when the surrounding layout is already loud.

Default links are better inside prose. Mono quiet links work better in metadata rows, sidebars, and terminal-adjacent UI.

Tables

Reference Tables

The dark head treatment is now a shared system pattern: `--ink-1` background with `--cyan-400` foreground for technical headers and reference surfaces.

Component Rule Why
Button 12px 24px inset Keeps controls aligned to the 12px rhythm while preserving a confident click target.
Card 24px interior padding Enough breathing room for dense content without softening the drafted structure.
Table head --ink-1 + --cyan-400 Creates a reusable technical-header pattern that reads cleanly in dark mode.
Link Accent only where needed Preserves semantic color meaning across marketing, docs, and product UI.

This table style is now shared through `colors_and_type.css`, not defined only in the gallery page.

## Issues Encountered

### Parity tool compared against a stale `qi` on PATH (the "TOC divergence" red herring)

- **Symptom:** TOC import order diverged only on larger Go/C/Python projects (same line count, different order); web trailed `github.com/...`, native interleaved alphabetically.
- **Root Cause:** The harness invokes `qi` from `PATH`, which was a **stale installed binary** built from a different source tree that sorted imports. This worktree's own `build/qi` produced line order — matching the web. The web was correct relative to its source.
- **Fix:** Confirmed via `build/qi` vs `/usr/local/bin/qi`. User then merged main (which brought the alphabetical sort into `shared/toc.c` as the intended behavior) and reinstalled; the web was updated to sort to match. User explicitly chose to keep PATH `qi` as the canonical reference.
- **Regression Risk:** `LOW`
- **Follow-Up:** Harness trusts PATH `qi`; stays correct only if the user reinstalls after source changes (their stated workflow).

### `%Q` unsupported by the web `sqlite3_mprintf` shim

- **Symptom:** No-results count SQLs emitted as `... full_symbol LIKE  ESCAPE '\'` (empty pattern) → every count read 0/-1.
- **Root Cause:** The WASM build's `sqlite3_mprintf` shim only implements `%q`/`%s`/`%d`; `%Q` produced nothing. (Its `%q` already adds surrounding quotes — behaves like real SQLite `%Q`.)
- **Fix:** Switched the `NR_EXACT`/`NR_WILD` count SQLs to `%q` (no manual quotes).
- **Regression Risk:** `NONE`
- **Follow-Up:** `NONE`

### Shell cwd persistence tripped a batch run

- **Symptom:** `node test/web-harness/parity.mjs --batch` failed with `MODULE_NOT_FOUND` for `parity.mjs`.
- **Root Cause:** An earlier `cd html/sources/negroni` persisted in the Bash tool's working directory; the relative path no longer resolved.
- **Fix:** Run from repo root with an explicit `cd`.
- **Regression Risk:** `NONE`

## Residual Risks / Not Verified

- **Host-only zero-results notes deferred:** `Note: 'X' is a keyword/stopword/too short…` need language word lists absent in WASM; such patterns get the partial-match probe instead. Divergence limited to genuinely unindexable patterns.
- **Multi-pattern auto-retry:** retry is single-pattern only (`NR_RETRY_SQL` built for one pattern). Multi-pattern zero-results emit the diagnostic lines but don't auto-retry.
- **Deferred count-dependent header lines:** `Filtering by file: … (N files)` and `Within symbol(s): … (N instances)` not yet emitted by the web (need a DB count the worker owns).
- **Retry-still-zero-after-filters:** rare edge (wildcard matches exist but filters exclude all) may diverge slightly; not exercised.
- Parity validated only against the curated ~50-file demo repos.

## Notes / Design Decisions

- **`HDR|` metadata over reformatting in JS:** header lines are composed in `qi_web_build` (where the parsed structures live) and echoed by the formatter, keeping parity-sensitive wording in C.
- **`suppress_header` flag** lets the no-results retry re-run the full pipeline without reprinting `Searching for:` — mirrors native's `goto retry_query` (header printed once, before the retry).
- **Retry via command-string rewrite** (`wildcardPattern`) re-enters `runQuery` so the wildcard query reuses all machinery (count, breakdown, source fetch); the `%`-gate prevents recursion.
- **Parity differ normalizes symmetrically** (both sides) so nothing real is hidden; deliberately does *not* normalize away header lines — that's how it caught #1–#4.

## Forward-Looking

1. **Emit the count-dependent header lines** (`Filtering by file: (N files)`, `Within symbol(s): (N instances)`) — needs a small protocol addition (a count SQL the worker runs, fed back to the formatter), the same pattern used for the zero-results counts.
2. **Multi-pattern auto-retry** — generalize `NR_RETRY_SQL` to wildcard the first eligible pattern among several (native's iterative `goto`).
3. **Run the parity batch on every language/edge combination in CI** (or fold `web-parity` into `web-test`) so future bridge changes can't silently drift; consider asserting `build/qi` ↔ installed `qi` agree to catch the stale-binary trap automatically.

## Documentation Ideas

1. **A "web bridge protocol" reference** listing every `build_info` key (`SQL`, `COUNT_SQL`, `MODE`, `NEEDS_SOURCE`, `HDR|`, `NR_*`, …), who emits it, who consumes it, and ordering/escaping rules. The keys are discoverable only by grepping.

## Freeform Thoughts

The single most valuable thing this session produced wasn't a fix — it was the tool. Three of the six "divergences" were real web bugs, but one (TOC import order) was the *harness* lying because it trusted a stale binary, and the right move was to stop and prove which binary was authoritative rather than "fix" the web to match a phantom. The parity differ paid for itself by being honest enough (symmetric normalization, no hiding header lines) to surface gaps, and the `build/qi` vs PATH investigation is the kind of thing that's invisible until you compare source-built artifacts directly. Worth internalizing: when a parity tool reports a diff, the *reference* is a hypothesis too.

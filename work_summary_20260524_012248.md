## Issues Encountered

### `Emscripten Header Dependency Leakage`

- **Symptom:** `The first make web attempt failed immediately because query-index-web.c inherited sqlite3.h and tree_sitter/api.h dependencies through shared headers.`
- **Root Cause:** `The extracted web slice was still including broad shared headers whose declarations mix browser-relevant query types with heavier CLI/indexer dependencies.`
- **Fix:** `Removed the broad header includes from query-index-web.c and replaced them with narrow local declarations for the currently extracted slice so emcc could compile the file incrementally.`
- **Regression Risk:** `LOW`
- **Follow-Up:** `Replace the temporary local declarations with smaller shared headers once the extraction surface is clearer and stable enough to justify that cleanup.`

### `Web Target Scope Definition`

- **Symptom:** `A naive web target would have implied a linkable browser module before the extracted query surface and SQLite WASM linkage exist.`
- **Root Cause:** `The current extraction is still at the helper layer; pretending the target was already link-complete would blur the real state of the port.`
- **Fix:** `Defined the Makefile web target as a compile-only Emscripten smoke build for now, with explicit comments that it is intentionally not yet a full JS/WASM output target.`
- **Regression Risk:** `LOW`
- **Follow-Up:** `Promote the web target from compile-only to a real linked module only after query-index-web.c has a stable exported entrypoint and the necessary SQLite/runtime pieces are intentionally wired in.`

## Notes / Design Decisions

- `Chose incremental extraction into query-index-web.c rather than splitting query-index.c, because preserving the existing CLI implementation as the behavior reference reduces risk while the WASM boundary is still being discovered.`
- `Used three boundary labels instead of a binary split: WEB_SAFE, HOST_ONLY, and HOST_BRIDGED. That distinction matters because features like source expansion are not pure browser-safe code today, but they are still part of the intended web feature set.`
- `Defined the initial Makefile web target as a compile-only Emscripten smoke build to keep the build truthful and useful while the real linked browser module is still under construction.`

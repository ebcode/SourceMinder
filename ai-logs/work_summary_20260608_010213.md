## Issues Encountered

### Stale `.db-wal` produces false-success indexing

- **Symptom:** `./index-c .` printed `Failed to commit transaction: cannot commit - no transaction is active` and then `Indexing complete: 114 files processed` (a false success), caused by a leftover `code-index.db-wal`.
- **Root Cause:** `db_begin_transaction()` and `db_commit_transaction()` return codes were ignored. SQLite's `BEGIN` is *deferred* (returns OK immediately), so the failure only surfaced at `COMMIT` — which then ran with no active transaction. Indexing continued and reported success regardless.
- **Fix:** Check both return codes in `indexer_main.c`; on failure clean up and `return 1` with an actionable message naming the `<db>-wal`/`<db>-shm` files to remove.
- **Regression Risk:** `LOW` — only adds early-exit on a previously-ignored error path; happy path unchanged.
- **Follow-Up:** The daemon-loop begin/commit (indexer_main.c ~677/731) still ignore returns; left intentionally (different failure semantics for a long-running watcher).

### Incorrect claim that schema columns are configure-independent

- **Symptom:** I asserted OOP columns (`scope`/`namespace`) are always present; user showed a `--enable-c` schema lacking them.
- **Root Cause:** I read `configure` (no conditional there) and didn't trace the `#ifdef`s in the schema DDL / `column_registry`.
- **Fix:** Corrected understanding; saved memory `project_schema_config_dependent`. Validates that committed `-v` goldens are fragile across configure profiles.
- **Regression Risk:** `NONE` (analysis only).
- **Follow-Up:** Golden-test robustness work still open (see Forward-Looking).

### `make tests`/`make install`/build-output confusion

- **Symptom:** (a) `make test` ran a stale `run-tests` binary; (b) user thought `index-rust` wasn't installed; (c) rust `gcc` appeared interleaved among symlinks.
- **Root Cause:** (a) `tests/run-tests` is built by its own target, not default `make`; (b) it *is* installed — the `cp` just appeared after a blank line; (c) parallel `make` fired each symlink as soon as its own binary was ready, before the slow rust link finished.
- **Fix:** (a) documented `make tests/run-tests`; (b) confirmed install correctness; (c) added `ALL_BINARIES` order-only barrier.
- **Regression Risk:** `LOW` — order-only deps don't trigger rebuilds.
- **Follow-Up:** `NONE`.

## Notes / Design Decisions

- **Why a column cap (`TOC_ALIGN_MAX_COLUMN`)**: pure "align to widest" lets a single long outlier (max real symbol is 40 chars: `handle_scoped_property_access_expression`) drag every short row's dot run wide. Capping at 40 keeps normal rows tight; symbols beyond the cap overflow rather than aligning. `SYMBOL_MAX_LENGTH` is 512, so the pathological 2-char-vs-256-char case is why the cap + overflow path exists.
- **Golden tests use `qi.args`**, not hardcoded `-v`, so future tests can pin explicit `--columns` sets — the path to making goldens robust across configure profiles (see memory).
- Left the `lint` target covering only `typescript/` + `shared/` (pre-existing gap, flagged not fixed).

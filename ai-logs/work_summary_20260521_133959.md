## Issues Encountered

### `cd -` not cross-platform
- **Symptom:** Initial "next steps" message used `cd -` which is bash-only
- **Root Cause:** Habit; `cd -` doesn't work in Windows cmd.exe
- **Fix:** Replaced with explicit "Return to the SourceMinder directory and run: make"
- **Regression Risk:** NONE
- **Follow-Up:** NONE

### `LANGUAGE_VERSION` not on first line of `parser.c`
- **Symptom:** Initial plan was to read first line of `parser.c` for grammar ABI version
- **Root Cause:** `#define LANGUAGE_VERSION` appears on line 7, 9, or 17 depending on the grammar
- **Fix:** Used `ts_language_abi_version(lang)` at runtime instead — returns the same value with no file parsing
- **Regression Risk:** NONE
- **Follow-Up:** NONE

### `grammar_parser_path` design abandoned
- **Symptom:** Initial plan included `grammar_parser_path` field in `IndexerConfig` for reading parser.c header
- **Root Cause:** Unnecessary once `ts_language_abi_version()` was identified as the right approach
- **Fix:** Replaced with `get_language` function pointer + `ts_language_abi_version()`
- **Regression Risk:** NONE
- **Follow-Up:** NONE

## Residual Risks / Not Verified

- `find_compatible_grammar_tag()` spawns up to 20 `popen()` calls (one per git tag); not benchmarked on repos with many tags — could be slow on very old clones
- `offer_grammar_downgrade()` runs `git checkout` via `system()`-equivalent; no verification that the working tree is clean first (user could have local modifications to `parser.c`)
- `tree-sitter generate` step left to user — no check that `tree-sitter-cli` is installed or in PATH before printing the instruction
- Deferred output model: `preflight_validation_start`'s `verbose` parameter is currently ignored (marked `(void)verbose`) — if future checks need verbose-conditional behavior in `start`, this will need revisiting

## Notes / Design Decisions

- **`abi_check.h` uses `const void *(*)(void)` for `GetLanguageFunc`** to avoid pulling `<tree_sitter/api.h>` into `indexer_main.h`; the cast is resolved inside `abi_check.c`. Each language's `index-*.c` wraps its `tree_sitter_*()` in a `static const void *get_language_wrapper(void)` to avoid function pointer cast warnings.
- **Dropped `preflight_validation()` convenience wrapper** after design review against `software-design-precepts.md` — it was a shallow module over two functions with only one caller; adding it would have widened the interface unnecessarily every time a new check type was added.
- **Two-phase troubleshoot flow**: report phase (all deferred, silent) → `preflight_validation_end` prints → interactive phase. This keeps deferred-output invariant intact while allowing interactive prompts after the user has seen the full diagnosis.
- **Interactive mode strictly scoped**: only activates on `--troubleshoot` + `STDIN_IS_TTY()`. Daemon mode and CI/CD runs are never interactive.
- **Only `y`/`Y` accepted** for the downgrade prompt; Enter = no, anything else = no. Default is always the safe no-op.
- **Grammar downgrade caveat** surfaced to user: older grammar may have reduced Perl parse coverage.

## Forward-Looking

1. **Apply `get_language` / `grammar_dir` to other indexers** (c, go, php, python, typescript, rust) so `--troubleshoot` works across all languages, not just Perl.
2. **Grammar manifest file** (`grammars.deps` or similar) listing each grammar repo URL + pinned version, consumed by `configure` to auto-clone missing grammars at the right version — addresses the setup friction that caused the original user issue.
3. **Check for `tree-sitter` CLI in `offer_grammar_downgrade`**: before printing "run tree-sitter generate", check `which tree-sitter` / `tree-sitter --version` and report whether it's available and at what version.
4. **`git` availability check in troubleshoot**: add a `PF_HINT` if `git` is not found in PATH, rather than silently returning 0 from `find_compatible_grammar_tag`.

## Tooling Ideas

1. **ABI compatibility matrix tool**: a small script that, given a grammar repo and a range of tree-sitter library versions, produces a table of which grammar tags are compatible with which library ABI — would have made the "find the right downgrade tag" design much clearer upfront.
2. **Cross-platform `popen` test harness**: a small test binary that exercises the `#ifdef`-guarded popen commands (`ldd`, `otool`, `pkg-config`, `pacman`) on each platform and checks the output format — would have caught the `cd -` issue before it was written.

## Documentation Ideas

1. **`docs/ABI_COMPATIBILITY.md`**: explain the tree-sitter ABI versioning model (grammar ABI vs. library ABI range), why mismatches happen, and the two resolution paths — would have saved significant design discussion time.
2. **`--troubleshoot` output format spec**: a short doc showing expected output for each scenario (match, mismatch + tag found, mismatch + no tag, no git) — would have made the `PreflightReport`/`PF_HINT` design decisions faster to validate.

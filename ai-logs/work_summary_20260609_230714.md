## Issues Encountered

### `--exclude-dir` silently ignored during daemon watch

- **Symptom:** Copying files into an excluded directory while the daemon ran caused them to be indexed, producing duplicate rows for every symbol.
- **Root Cause:** `is_excluded()` was `static` with exactly one caller (`walk_directory()`). The watch loop consulted `ignore_dirs` (via `is_path_ignored()`) but never `exclude_dirs`.
- **Fix:** Exported matching logic as `exclude_dirs_match()`; called it in the event loop after the existing `is_path_ignored` block.
- **Regression Risk:** LOW — the initial-scan path (`walk_directory` → `is_excluded`) is unchanged; only event-loop code is new.
- **Follow-Up:** Existing duplicate rows in `code-index.db` (from pre-fix pollution in `./html/sources/sourceminder/`) may need manual cleanup or a fresh re-index.

## Notes / Design Decisions

- Filtering at the event-processing level in `indexer_main.c` was the right single cross-platform location — avoids touching three platform watcher backends.
- Returning the matched pattern string from `exclude_dirs_match()` (rather than a bool) eliminated the need for a second lookup to build the warning message.
- DELETED events intentionally bypass the exclude filter: this is the cleanup path for any rows that snuck in before the fix.

1. A section in `docs/ARCHITECTURE.md` covering the watch-loop event pipeline — specifically which filters run in order (`is_path_ignored` → `exclude_dirs_match` → event-type dispatch) — so future contributors know where to add new filters.
2. A `docs/DAEMON.md` page documenting daemon-specific flags (`--exclude-dir`, `--silent`, `ignore_files.txt`) with behavioral notes on what happens at watch time vs. initial scan — the current README treats them as equivalent, which is what caused this bug to go unnoticed.

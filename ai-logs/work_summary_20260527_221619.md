## Issues Encountered

### `--and` with `-i`/`-x` filter semantics

- **Symptom:** `qi fprintf stderr --and -i arg` returns no results because `-i arg` is applied inside each INTERSECT subquery, requiring BOTH patterns to appear as ARG. Since `fprintf` is always CALL, no lines qualify.
- **Root Cause:** Filters are applied in both the INTERSECT subqueries (for co-occurrence detection) and the outer query (for display). The subquery filtering is overly restrictive for the `--and` use case.
- **Fix:** Deferred. A more useful semantic would apply filters only to the outer displayed rows, so `--and` finds co-occurring lines regardless of context, and `-i`/`-x` controls which rows are shown.
- **Regression Risk:** LOW — current behavior is consistent, just less useful than it could be.
- **Follow-Up:** Remove `build_common_filters` from INTERSECT subqueries in `build_query_filters()`, keeping it only on the outer query.

## Notes / Design Decisions

- Bugs #4 and #5 were fixed together in a single refactor of `execute_proximity_to_temp_table()` — the per-pattern EXISTS approach inherently eliminates the per-anchor compilation overhead
- Bug #3 required converting standalone `if` statements to a unified `if/else if` chain — behaviorally equivalent since each `argv[i]` can only match one flag
- Kept the temp-table proximity approach rather than replacing it with the web bridge's INTERSECT approach, since the temp-table handles `line_range > 0` (multi-line proximity) which INTERSECT on `(directory, filename, line)` does not

## Forward-Looking

1. Fix `--and` filter semantics: move `build_common_filters` out of INTERSECT subqueries so `-i`/`-x` only filter displayed rows, not co-occurrence detection
2. Consider replacing the temp-table proximity approach entirely with an EXISTS self-join query (as suggested in the design note in NATIVE_CLI_FIXES_NEEDED.md) for simplicity and to eliminate duplicate insertion
3. These fixes should be tested against a broader set of codebases to verify no regressions in edge cases (especially the argument parsing chain change)

## Freeform Thoughts

The temp-table proximity approach in the native CLI is significantly more complex than the web bridge's single-query approach. The pre-compiled statement reuse (bug #5 fix) makes it performant, but the code is still ~120 lines of careful statement lifecycle management. If the EXISTS self-join approach from the design note can handle `line_range > 0`, it would be a worthwhile simplification. The current fix is correct and fast, but the conceptual weight is high for what should be a straightforward "are these patterns near each other?" query.

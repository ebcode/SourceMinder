## Work Completed

- **Bug #2** — Associated types (`type Item;`, GATs) now indexed as TYPE definitions with trait parent (`associated_type` dispatch + parent in `handle_type_item`).
- **Bug #3** — Turbofish calls (`.parse::<i32>()`) now CALL instead of PROP (`generic_function` unwrap in `handle_call_expression`).
- **Bug #4** — Chained method calls keep per-link parents (`a.b().c()` → `c`|`b`); `self` receivers recognized; shared `extract_receiver_parent()` helper used by call and field handlers.
- **Bug #5** — Braced use-groups get namespaces, including nested groups and aliases (`use a::{b::{C, D as E}}`); `index_use_tree` now threads an accumulated prefix.
- **Bug #6** — Inner attributes (`#![allow]`) no longer misattributed to the following item; `#[cfg]` on modules captured (`handle_mod_item` now extracts attributes).
- **Bug #7** — `extern crate` indexed as IMP (alias-aware); extern-block members get the block ABI as modifier (`extern "C"`, `extern "system"`); ABI string no longer leaks as STR.
- **Bug #8** — Struct-pattern shorthand bindings (`Rect { width, height } =>`) indexed as VARs (`shorthand_field_identifier` leaf).
- **Bug #9** — Punctuation-only string fragments (`:?` from format specs) no longer indexed (alnum requirement in Rust string handler).
- **Design: `mut` capture** — on lets, pattern bindings (`mut_pattern`), parameters, and statics; joins with extern ABI when both apply.
- **Design: parents** — struct fields → struct; variant fields → variant; associated consts → trait (only when direct `declaration_list` members, so function-local consts stay unparented).
- **Design: struct literals** — fields parented (var when assigned / enclosing field when nested / type name otherwise); literal type names indexed as CLASS usages with NS for scoped forms.
- **Design: scoped patterns** — `Shape::Circle =>` → CASE usage with NS `Shape`; bare constructors (`Ok(v)`, `Point { .. }`) → CLASS usages, including nested patterns.
- **Design: trait bounds** — inline bounds, where clauses, supertraits, and associated-type bounds indexed as TRAIT usages with NS for scoped paths (`index_trait_bounds` / `index_generic_constraints`, called from 7 handlers).
- **Design: derives** — `#[derive(Debug, Clone)]` contents indexed as TRAIT usages with clue `derive` (`handle_attribute_item`).
- **Docs** — Rewrote `docs/RUST_GUIDE.md` (1637 → ~600 lines): corrected non-working query forms, documented all new capabilities, added an honest "Filtered Symbols" limitation note, collapsed redundant sections, made all examples runnable against the sample sources.

## Notes / Design Decisions

- **Struct-literal field parents follow the C indexer** (assigned → variable, nested → enclosing field), with a Rust-only fallback to the literal's type name justified syntactically: Rust literals always name their type; C initializer lists don't.
- **Variant fields parent the variant** (`width` → `Rect`), not the enum — nearest syntactic parent, per the project's parent_symbol convention.
- **Associated consts parent only when direct members of a `declaration_list`**, so function-local `const PI` doesn't inherit an enclosing impl from `g_current_impl`.
- **Pattern constructors:** scoped paths → CASE usage (path implies Enum::Variant); bare names → CLASS usage (syntax can't distinguish `Some` from `Point`; chose consistency with struct-literal handling).
- **Derive traits get clue `derive`** so they're distinguishable from bounds: `qi Clone -i trait` finds both; `-c derive` isolates derives.
- **`.await` as MOD, macro calls via TYPE column** (`-t macro`) — existing conventions kept and now documented correctly.

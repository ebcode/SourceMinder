## Notes / Design Decisions

- **`MODE|help` + separate `qi_web_help()` export** mirrors the `MODE|toc` + `qi_web_toc_format()` pattern: `qi_web_build` signals the mode, the pipeline dispatches to the right formatter. Keeps `qi_web_build` free of formatted output and the pipeline's mode branches symmetric.
- **`--db-file` and config-file note omitted from web help** — these flags don't exist in the WASM context. Omitting them avoids confusing browser users who have no local filesystem or `.smconfig`.
- **Error message updated to match new alias** — `"Commands must start with 'query-index', or 'qi'."` lists the long form first (more recognizable to users coming from CLI docs), with `qi` as the short alias.

## Tooling Ideas

1. **`make web-quick`** — a Makefile target that skips the content-hash copy step and just rebuilds `qi-web.js`/`qi-web.wasm` in place. The hash + manifest shuffle adds several seconds per iteration; during active C development where the hash doesn't matter yet, a plain rebuild target would tighten the loop.
2. **`qi_web_build` smoke runner** — a tiny Node script (not the full harness) that accepts a command string, calls `qi_web_build` via the existing WASM loader, and pretty-prints the `buildLines` object. Would have let me verify `MODE|help` in seconds instead of needing to add a test case and run the full suite.

## Documentation Ideas

1. **`MODE|*` protocol table in `QUERY-INDEX-WEB-DEVELOPMENT-GUIDE.md`** — a table listing every `MODE` value (`toc`, `files`, `help`), which `qi_web_build` condition sets it, which pipeline branch handles it, and which C formatter is called. Adding `MODE|help` this session required reading all three prior mode implementations to understand the pattern; a table would have made it a one-minute lookup.
2. **"Adding a new no-DB command" recipe** — a short checklist: (1) add flag field to `WebCommand`, (2) detect in `parse_command()`, (3) override no-patterns error in `qi_web_build()` if needed, (4) emit `MODE|<name>`, (5) add C formatter export + Makefile entry, (6) add pipeline branch. The `--help` implementation followed this pattern exactly; documenting it makes the next no-DB command (e.g. `--version`, `--list-types`) trivial to add.

## Freeform Thoughts

The `--help` feature is small but closes a real UX gap — a user who discovers the browser terminal and types `qi --help` now gets a response instead of an error. The pattern it follows (`MODE|help` + separate export) is the right one for any future no-DB command, and the recipe is now implicit in the code even if not yet written up.

The `query-index` alias is a single `strcmp` but worth having: users who know the native CLI name will naturally try it. Updating the error message to list `query-index` first was the right call — it's the canonical name, `qi` is the shorthand.

The one rough edge this session: loading `qi-web.js` outside the harness infrastructure is harder than it should be because of the CJS/ESM `__dirname` mismatch in the Emscripten output. This is a known Emscripten limitation for older output modes; it surfaced as wasted time on a dead-end test script before falling back to the proper harness. The `qi_web_build` smoke runner idea above would solve this for future single-function probing.

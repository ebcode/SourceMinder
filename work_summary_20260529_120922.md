## Issues Encountered

### `strcasecmp` undeclared in web-smoke target

- **Symptom:** `make web-smoke` failed with `error: call to undeclared function 'strcasecmp'` after adding `map_context_web()` to `query-index-web.c`.
- **Root Cause:** The `web-smoke` target compiles `query-index-web.c` without `-D_POSIX_C_SOURCE=200809L`, so `<string.h>` does not expose `strcasecmp`. The full `web` target includes that flag so the issue was latent there.
- **Fix:** Added `#include <strings.h>` to `query-index-web.c` — `strcasecmp` is declared there unconditionally on POSIX systems and in Emscripten's sysroot.
- **Regression Risk:** NONE
- **Follow-Up:** NONE

## Notes / Design Decisions

- **`map_context_web()` in `query-index-web.c`**: Placed here rather than in `qi-web-entry.c` because it is query-domain knowledge (context type names), not entry-point logic. Eliminates the duplicate `static map_context()` that had lived in `qi-web-entry.c`.
- **`qi_web_format_breakdown` as a separate export**: Mirrors the CLI's architecture — `get_context_summary()` is a sibling call to `print_results_by_file()`, not a parameter to it. The breakdown is generated and formatted independently; the caller decides whether to invoke it.
- **`qi_web_format_files` as a separate export**: Same reasoning as breakdown — `print_files_only()` in the CLI is a completely separate function, not a mode of the main formatter. Consistent with the `--toc` pattern (`qi_web_toc_format`).
- **Files mode branch after `POPULATE_COL_FILTER`**: Unlike `--toc` which builds its own structures and returns early, `--files` reuses the standard PatternList/ContextTypeLists/QueryFilters already built by the shared setup code. Avoids duplicating the structure-building logic.
- **Breakdown condition mirrors CLI exactly**: `total > rows.length` (web) ≡ `limit > 0 && total_count >= limit` (CLI). Breakdown is informational — only shown when the user might not be seeing everything.

## Documentation Ideas

1. **Build-info protocol reference**: The `build_info` key/value wire format (`PATTERNS|`, `SQL|`, `COUNT_SQL|`, `BREAKDOWN_SQL|`, `FILES_SQL|`, `MODE|`, `LIMIT|`, `NEEDS_SOURCE|`, `WITHIN_SQL|`, `WITHIN_SYMBOLS|`, etc.) is the central contract between `qi_web_build` and the worker/format functions, but it is completely undocumented. A short reference table (key, producer, consumer, format, semantics) would make the bridge protocol self-describing and reduce the need to reverse-engineer it from C source on every session.
2. **"Web vs. CLI differences" document**: A concise table of behavioral differences between the native CLI and the web bridge — e.g., breakdown only shown when results are truncated, `--toc` requires `-f` in the web but not the CLI, proximity search uses EXISTS self-join (not temp tables) so performance characteristics differ, source flags require a static file server at the same origin. Would have been useful as a quick reference when verifying parity and deciding whether a difference is a bug or a known divergence.

## Issues Encountered

### Daemon indexed files under --exclude-dir'd path

- **Symptom:** Copying demo sources triggered `Reindexed: ./html/sources/sourceminder/...` despite `--exclude-dir html/sources`; 156 duplicate files entered the dev db, doubling qi results mid-session.
- **Root Cause:** `--exclude-dir` enforced only in the initial walk (`is_excluded`, one caller); the watch loop checks config `ignore_dirs` but never `exclude_dirs`; watcher backends watch excluded dirs.
- **Fix:** Documented in `FIX_EXCLUDE_DIRS_WATCH.md` (main-branch work); Eli recreated the db cleanly.
- **Regression Risk:** `NONE` (no code changed this session)
- **Follow-Up:** Implement the plan on main.

### Harness tests coupled to html/projects.json first entry

- **Symptom:** Restoring sourceminder to projects.json flipped the default test project, and the negroni-fixture tests (incl. the new `--parent-type Logger` case) would have broken; conversely removing it for release breaks the sourceminder tests — the original corner.
- **Root Cause:** `loadProject()` duplicated in both harnesses, reading only the deployment manifest.
- **Fix:** `manifest.mjs` + `projects.test.json` + `make test-web-db`; deployment manifest now release-only.
- **Regression Risk:** LOW — `--project negroni` fallback verified.
- **Follow-Up:** NONE

### copy-demo-sources.sh tty-detection silently copied 0 files

- **Symptom:** First stdin-aware version copied 0 files when run non-interactively without piped input (stdin non-tty → read empty stdin).
- **Root Cause:** `[ -t 0 ]` mode detection conflates "not a terminal" with "data piped in".
- **Fix:** Explicit `-` argument selects stdin mode; default always runs `qi % --files`.
- **Regression Risk:** NONE — both modes verified identical (157 files).
- **Follow-Up:** NONE

### C ARG rows carry types but no parent_symbol

- **Symptom:** New query #14 (same-type parameter runs) returned empty when grouped by `parent_symbol`; inspection showed C parameter rows have `type` set and `parent_symbol` empty.
- **Root Cause:** `c_language.c` doesn't parent parameters to their function; Python/TS do (`.parent = parent_function`). Another per-language drift of the FIX_PAR_NS shape.
- **Fix:** Query reworked to group by definition line with nearest-preceding-FUNC lookup; gap recorded as FIX_PAR_NS.md open question #5.
- **Regression Risk:** NONE
- **Follow-Up:** Decide whether C ARG parenting folds into the FIX_PAR_NS pass.

## Notes / Design Decisions

- **Web EXISTS clause qualifies outer refs as `code_index.` when col_prefix is empty** — inside the correlated subquery, bare names resolve to `def`; with the `ci.` proximity alias the prefix is used directly. This is the one web-specific deviation from the native clause.
- **`--parent-type` sets `cmd.cf.parent.show = 1`**, mirroring native's `show_columns.parent_symbol = 1` — there is no parent_type display column, the PAR column is surfaced instead.
- **Harness manifests resolved against their own base dir** (repo root vs html/), so one loader serves both worlds; `--project` searches test manifest first, then deployment.
- **`test-web-db` indexes the working tree itself** rather than a copied corpus — the richest available C corpus, always schema-current, nothing to hand-refresh. `--exclude-dir html` keeps demo copies out (the ignore list already covers build/tmp/grammars).
- **Explicit `-` beats tty-detection** for stdin-mode CLI scripts — silent 0-file "success" in cron/make contexts is worse than requiring one character.
- **Quality queries as conformance probes**: two structurally-empty results this session were indexer gaps (method-def parents; C ARG parents), not query bugs. WHY_THIS_SCHEMA.md captures this as "the schema doubles as its own conformance oracle."

## Tooling Ideas

1. **`qi --count-by <column>`** — a GROUP BY mode (`qi % -i arg --count-by parent` → counts per parent). Every quality-query iteration this session dropped to raw sqlite3 solely for aggregation; counts-per-column over the existing filter pipeline would keep ~half of those in qi, with the filter flags already composing correctly.
2. **Harness fixture lint** — a `run.mjs --check-fixtures` mode that, before running, verifies each case's `expect` fragments exist in the selected project's db (via a cheap LIKE probe). The negroni→sourceminder retargeting and the `--parent-type Logger` near-miss were both this class of error; a lint would catch them at authoring time instead of as test failures.

## Freeform Thoughts

The session had an unusually clean arc: a feature port (--parent-type, done in an hour with full parity), then each verification step opened the next door — running parity exposed the TOC drift, restoring sourceminder exposed the harness coupling, the copy script exposed the watcher bug, and the quality queries exposed two indexer gaps. None of these were sought; all were found by running things end-to-end against real data. The dogfooding loop main's summary praised is still paying out.

The exclude-dir watcher bug deserves its priority: it silently corrupted the dev database *during* the session, and the only symptom was qi results quietly doubling. Index-integrity bugs are worse than query bugs because they outlive the session that causes them.

A meta-observation on the quality queries: their value wasn't the metrics (most top-N lists confirmed the obvious) — it was the *empty* results. "This query can't return rows on this schema" turned out to be the sharpest indexer-gap detector we have. That inverts the usual relationship between tests and data: the queries audit the indexer, not the code. Worth keeping a handful of them runnable in CI against a fixture corpus once INDEXING_SEMANTICS.md exists to define expected-nonempty.

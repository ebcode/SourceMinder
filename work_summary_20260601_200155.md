## Issues Encountered

### `projectSelectEl is null` on page load

- **Symptom:** `Uncaught TypeError: can't access property "addEventListener", projectSelectEl is null` in the browser console immediately on load.
- **Root Cause:** `sourceminder-wasm.html` was missing all six DOM elements that `app.js` binds at module evaluation time.
- **Fix:** Added `#status`, `#summary`, `#terminal-container`, `#error`, `#project-select`, `#project-download` to the HTML; moved scripts to end of `<body>`.
- **Regression Risk:** `NONE`
- **Follow-Up:** `NONE`

### Orphaned "Download" text when link is hidden

- **Symptom:** After wrapping the anchor with static "Download" prefix text, the word "Download" would remain visible even when `app.js` set `projectDownloadEl.hidden = true` (the `hidden` attribute only hides the `<a>`, not the surrounding text node).
- **Root Cause:** `hidden` is an element attribute; text nodes are not elements and cannot be hidden by it.
- **Fix:** Wrapped the prefix, anchor, and size span in `.download-wrap`; added `.download-wrap:has(#project-download[hidden]) { display: none; }` to hide the whole group when the anchor is hidden.
- **Regression Risk:** `NONE`
- **Follow-Up:** `NONE`

### `var progressMsg` declared twice in `"progress"` case

- **Symptom:** Potential linter warning from two `var progressMsg` declarations in separate branches of the same `switch` case.
- **Root Cause:** Initial edit declared `var progressMsg` inside both the `if` and `else` branches.
- **Fix:** Hoisted `var progressMsg` to the top of the case, assigned without `var` in each branch.
- **Regression Risk:** `NONE`
- **Follow-Up:** `NONE`

## Residual Risks / Not Verified

- **Auto-query on first load** (`qi % -f logger.go --toc`) is a leftover from `index.html` development. On `sourceminder-wasm.html` it will run against the sourceminder DB and may produce unexpected or unimpressive output as the demo's opening move.
- **No loading indicator before the terminal mounts.** `#load-status` only appears after the project bar renders. Between page load and the first worker message, the terminal container is blank with no visual affordance. A CSS animation on `.term` or a placeholder text node in `#terminal-container` would close this gap.
- **`#project-select` hidden until projects load** leaves the "Project" label floating alone. The `:has()` CSS trick used for the download group could hide the entire `.project-bar-left` until the select is visible.
- **`index.html` download link** now shows filename only (no "Download" prefix) since the `textContent` change in `app.js` is shared. Minor regression — the label was changed intentionally for `sourceminder-wasm.html` but affects both pages.

## Notes / Design Decisions

- **Null-guard pattern for page-specific elements:** `loadStatusEl` and `sizeEl` are looked up by ID and checked before use, so the same `app.js` serves both pages without branching on page identity. New per-page features should follow this pattern.
- **CSS-only suppression of shared elements:** `#status` and `#summary` are hidden via `display: none !important` rather than removing them from the DOM — `app.js` still writes to them safely; the page just doesn't show the output.
- **`:has()` for coupled visibility:** Used twice this session (`download-wrap`, and implicitly for future project-bar-left). Modern browser support is broad enough for a landing page context.

## Tooling Ideas

1. **`make serve-html`** — a one-liner that starts a local HTTP server rooted at `html/` with file-watching and auto-reload. Every CSS/HTML iteration this session required a manual browser refresh; live reload would have cut the feedback loop significantly.
2. **A DOM-requirements linter for `app.js`** — a small script that statically extracts all `document.getElementById(...)` calls in `app.js` and checks that each ID exists in every `html/*.html` file that includes `app.js`. Would have caught the `projectSelectEl is null` crash before the first browser load.

## Freeform Thoughts

The `:has()` trick (used twice: download-wrap visibility, and flagged for project-bar-left) felt like the right tool — it keeps visibility logic in CSS where it belongs, instead of adding JS event listeners to toggle classes. Worth encoding in the new-page checklist.

The null-guard pattern for page-specific elements in `app.js` (`if (loadStatusEl) ...`) is clean but relies on discipline. If `app.js` grows many such guards it will become hard to reason about. A future refactor might separate the "page adapter" layer into a thin `sourceminder-wasm-app.js` that imports from a core `app-core.js` — but that's premature for two pages.

The `index.html` download link regression (filename only, no "Download" prefix) is worth flagging: it was a side effect of an intentional change for `sourceminder-wasm.html`. Small, but the kind of thing that accumulates. The DOM-requirements linter idea above would help catch this class of cross-page side effect.

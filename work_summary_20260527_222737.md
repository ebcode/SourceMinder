## Issues Encountered

### `COUNT(DISTINCT directory, filename)` is not valid SQLite syntax

- **Symptom:** First replacement for the concatenation-collision bug used `COUNT(DISTINCT col1, col2)`, which SQLite rejects with "wrong number of arguments to function COUNT()".
- **Root Cause:** SQLite's `COUNT()` only accepts a single expression; multi-column DISTINCT requires a subquery.
- **Fix:** Used `SELECT COUNT(*) FROM (SELECT DISTINCT directory, filename FROM code_index ...)` in both C functions and the JS worker summary query.
- **Regression Risk:** `LOW`
- **Follow-Up:** `NONE`

### EXISTS self-join performance on broad `--and` queries

- **Symptom:** `qi malloc free strcmp --and 10` took ~860ms per query (COUNT + main = ~1.7s total).
- **Root Cause:** Each of 3 EXISTS clauses does a correlated subquery scan. With ~6K candidate rows, that's ~18K subquery evaluations, each scanning for matching `(directory, filename, symbol, line ± range)`. The `COUNT_SQL|` optimization avoids duplicate WHERE evaluation but cannot eliminate the EXISTS cost.
- **Fix:** Emitted separate `COUNT_SQL|` to avoid wrapping in `SELECT COUNT(*) FROM (sql LIMIT -1)`. Accepted remaining cost as inherent to the EXISTS approach. Noted that a composite index on `(directory, filename, symbol, line)` would help significantly.
- **Regression Risk:** `LOW`
- **Follow-Up:** `NONE` (accepted for now)

### `cmd` value vs. pointer mismatch in OOM macros

- **Symptom:** `SET_CMD_ERROR(cmd, ...)` failed because `cmd` inside `parse_command` is a `WebCommand` value, not a pointer.
- **Root Cause:** The macro uses `(cmd)->` which requires a pointer.
- **Fix:** All `SET_CMD_ERROR` calls pass `&cmd`. All `cmd_strdup` calls pass `&cmd`. `parse_col_flag_values` gained a `WebCommand *cmd` parameter.
- **Regression Risk:** `LOW`
- **Follow-Up:** `NONE`

## Residual Risks / Not Verified

- EXISTS self-join performance with ~62K-row index: 3-pattern `--and 10` takes ~1.7s total (COUNT + main). Acceptable for interactive use on this scale but a composite index on `(directory, filename, symbol, line)` would help.
- The `COUNT_SQL|` derivation uses `strstr("SELECT * ", ...)` and `strstr("ORDER BY", ...)` — relies on the main SQL always starting with `SELECT * ` and containing exactly one `ORDER BY` clause. This holds for all current query paths but is fragile if SQL generation changes.
- Within WHERE clause injection uses string concatenation in JS — directory/filename values are SQL-quoted via `replace(/'/g, "''")`. This matches SQLite's escaping convention but relies on the values not containing other special characters.

## Notes / Design Decisions

- **EXISTS over temp tables**: Chose self-join EXISTS for `--and` with range because it produces a single SQL statement, naturally deduplicates (temp tables can insert duplicates when anchor ranges overlap), handles wildcard patterns correctly (EXISTS checks presence, not a distinct-symbol count), and requires no multi-statement bridge protocol or sqlite3 in WASM. The performance cost of correlated subqueries is acceptable for interactive use.
- **JS-side within lookup**: Since the JS worker already owns the DB, the within lookup (finding definition source locations) is done in JS rather than adding sqlite3 to the WASM module. This keeps the WASM binary small (34K) and the bridge protocol simple.
- **Shared `find_build_line` helper**: Replaced 4 `strstr`-based metadata lookups with a single line-anchored parser that matches `KEY|value` only at line starts. This prevents false matches when SQL text happens to contain `COLUMNS|`, `DEBUG|`, etc.
- **`WebOutput.error` flag**: Instead of checking `wo_printf` return values at every call site, the error flag propagates through all output operations and is checked once at `wo_steal` time. All four return points in `qi_web_build` and `qi_web_format` fall back to `strdup("ERROR|out of memory")` when steal returns NULL.
- **Rejected**: File grouping `PATH_MAX_LENGTH` truncation fix — user accepts constraint for web repos.
- **Rejected**: Removing native CLI fixes from `query-index.c` — user wants to defer to a separate branch.

## Freeform Thoughts

The EXISTS self-join approach for `--and` was satisfying because it's architecturally clean — a single SQL statement that naturally handles deduplication, wildcards, and filters — but the performance cost at scale is real. On this 62K-row index, a 3-pattern `--and 10` takes ~850ms per query. That's acceptable for interactive use but would be painful on a million-row index. The temp-table approach in the native CLI is also slow (N+1 queries, per-anchor prepares), so both approaches have scaling problems. The right answer for production is probably a composite index plus an EXISTS-based approach, trading a slightly larger DB for consistent query performance.

The line-by-line review of `qi-web-entry.c` and `query-index-web.c` was productive — it caught real bugs (extension shorthand wildcard collision, INTERSECT outer filter omission, `--within` partial-match, OOM safety) that would have been painful to discover through testing alone. The total deletion of ~620 lines of dead counting/temp-table code felt like the right endpoint for the extraction effort: the web bridge is now a tight single-query SQL builder with a thin JS execution layer, not a partial port carrying unused CLI baggage.

The `NATIVE_CLI_FIXES_NEEDED.md` file effectively defers 6 bugs to the CLI branch, keeping this session focused on the web bridge while not losing the findings. The pattern of discovering bugs in the web extraction and then checking whether they also exist in the native CLI was valuable — in several cases (extension shorthand, INTERSECT outer filter, unknown flags) both implementations had the same issue.

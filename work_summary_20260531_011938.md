## Issues Encountered

### `--debug` gated on the wrong "debug"

- **Symptom:** Initial pipeline edit appended the `DEBUG_*` SQL keys under `if (debug)`, which would have printed nothing for an actual `qi ... --debug` command.
- **Root Cause:** `debug` in `qi-pipeline.js` is `ctx.debug` (the logging toggle), entirely separate from the command's `--debug` flag, which surfaces as `DEBUG|1` in build_info.
- **Fix:** Gated the `DEBUG_*` appends and the breakdown `debug_sql` arg on `buildLines.DEBUG === '1'`.
- **Regression Risk:** `NONE`
- **Follow-Up:** `NONE`

### `run.mjs` defaults to the negroni project

- **Symptom:** `node test/web-harness/run.mjs` reported 6 failures including the new `--debug` case (missing `[Get total count]`/`[Get context summary]`).
- **Root Cause:** With no `--project`, `loadProject()` returns the first manifest entry (negroni, a Go repo). The integration cases — and my new one — assume the sourceminder snapshot; `malloc -f shared/` returns 0 rows on negroni, so the early "No results" return skips the count/breakdown lines.
- **Fix:** Run with `--project sourceminder` (as `check-parity.sh` does by default). 16/16 there. The negroni failures are pre-existing harness misuse, not regressions.
- **Regression Risk:** `NONE`
- **Follow-Up:** `run.mjs` could default to (or hard-pin) sourceminder, or skip project-specific cases when the loaded project doesn't match — see Tooling Ideas.

### Reflexive grep instead of qi

- **Symptom:** Used `grep`/`rg` several times on indexed files (`app.js`, `parity.mjs`) without alerting; the user pushed back twice.
- **Root Cause:** Muscle memory — assumed multi-word phrases forced an rg fallback and that `| head` was needed to trim output.
- **Fix:** `qi %within% %symbol% --and` for phrases; `qi '\--full'` to escape leading-flag patterns; `--limit N` instead of `| head`. Saved all three to memory and hardened the qi-first / always-alert rule.
- **Regression Risk:** `NONE`
- **Follow-Up:** `NONE`

## Notes / Design Decisions

- **`--debug` is an intentional, documented divergence, not a parity target.** Native's `?`-bound SQL can't be pasted into sqlite3; the web's inlined form can. Verified copy-paste reproducibility against the actual downloadable `.db`. This is the through-line that connects the download-link side-quest to the `--debug` work: download the DB, copy a `--debug` query, run it, see the same numbers.
- **`--full` overflow is a feature, not a bug.** Width is measured from the compact stored value (`MAX(LENGTH(context))`), but the full name is rendered — so `FUNCTION` overflows its column. Reproducing that required expanding *only* at render time and leaving the width pass alone.
- **No new ccall signatures for counts** — `WITHIN_COUNT` piggybacks on the build_info string, same trick as `FILE_FILTER_COUNT`. Only `qi_web_format_breakdown` got a new arg (unavoidable — the breakdown is a separate call and the summary SQL line belongs to it).

## Tooling Ideas

1. **`run.mjs` project guard** — default to (or require) `--project sourceminder`, and auto-skip cases whose expectations don't match the loaded project, so a bare `node run.mjs` doesn't emit misleading negroni failures.
2. **`make web-debug "<qi cmd>"`** — dump the full `qi_web_build` build_info (all `*_SQL` and `DEBUG_*` keys) for one command under Node. I leaned on `check-parity.sh "<cmd>"` + `grep '^  +'` to read the web's emitted SQL; a first-class dump would have made the `DEBUG_*` plumbing instant to inspect.

## Issues Encountered

### Config.h overriding emcc `-DENABLE_TYPESCRIPT=1`

- **Symptom:** `make web` failed with `no member named 'scope' in 'QueryFilters'` despite `-DENABLE_TYPESCRIPT=1` on the compile line.
- **Root Cause:** `config.h` (generated by `./configure`) unconditionally `#define ENABLE_TYPESCRIPT 0`, overriding the command-line flag since it's included after `-D`.
- **Fix:** Added `#undef ENABLE_TYPESCRIPT` / `#define ENABLE_TYPESCRIPT 1` in `query-index-web.h` after `#include "config.h"`.
- **Regression Risk:** `LOW`
- **Follow-Up:** `NONE`

### TOC worker returning "No SQL built" error

- **Symptom:** Browser showed `Error: No SQL built for query.` for `qi % -f qi-web-entry.c --toc`.
- **Root Cause:** TOC mode check was placed AFTER the `if (!sql)` guard; TOC emits `TOC_SQL|` not `SQL|`, so `buildLines.SQL` was undefined.
- **Fix:** Moved the TOC mode handler before the `if (!sql)` check so it short-circuits with its own pipeline.
- **Regression Risk:** `LOW`
- **Follow-Up:** `NONE`

### Double-LIMIT in TOC SQL

- **Symptom:** `SQLITE_ERROR: near "LIMIT": syntax error`.
- **Root Cause:** `build_toc_web_sql()` appended `LIMIT 25` to the SQL, and the worker also appended `LIMIT 25`.
- **Fix:** Removed LIMIT from the SQL builder; worker always handles limit (consistent with regular query path).
- **Regression Risk:** `LOW`
- **Follow-Up:** `NONE`

## Residual Risks / Not Verified

- The hash-set probe limit (256 steps for 256 slots) silently drops entries if the table fills — acceptable per the stated 255-import ceiling, but would allow duplicates in output if exceeded.
- The `last_idx` cache in file grouping assumes rows arrive ordered by `(directory, filename, line)` from the TOC SQL. If the DB ordering changes, O(N·F) scans resume but correctness is unaffected.
- `toc_find_build_line` is duplicated between `qi-web-entry.c` and `toc-web.c` — could be extracted to a shared header, but the duplication is 12 lines and both files are linked into the same WASM module.

## Notes / Design Decisions

- **Separate format function over multi-mode `qi_web_format`.** TOC output is structurally different (file sections, context-type headers, dot-padded symbols) from the table-based search output. A dedicated `qi_web_toc_format` keeps the code clear and avoids conditional complexity in the main format path.
- **Ownership transfer over `strdup`.** `build_toc_web_sql` returns `b.sql` directly (NULLing it before `free_sql_builder`), eliminating an unnecessary full-string copy.
- **Hash set over sorted array for import dedup.** A 256-slot open-addressing hash set gives O(1) average lookup/insert while preserving first-seen order (unlike the sort-then-dedup alternative, which reorders imports alphabetically).
- **Clamp over dynamic padding.** Padding dots use `%.*s` against a fixed 70-char literal with a clamp — avoids per-dot function calls without introducing a variable-length dot builder.
- **Build-info protocol over multiple format parameters.** TOC includes are passed through the existing build_info string protocol (`TOC_INCLUDES|`) rather than adding a new parameter to `format_toc_web`, keeping the bridge API surface compact.

## Freeform Thoughts

The TOC flag was the last "large" architectural question mark in the web bridge — it was classified as HOST_BRIDGED in the plan, but turned out to be purely database-driven. The extraction went smoothly because `build_toc_query` was already WEB_SAFE: it just needed a `SqlBuilder` wrapper (to replace the static 8KB buffer) and a new format function. The real work was in the format function (section grouping, dot padding, import dedup) and the review-driven hardening (OOM safety, performance, parity).

The review cycle was productive — the 10 flagged issues covered the full spectrum: memory leaks, undefined behavior, OOM correctness, algorithmic complexity, and output parity. Six of those issues also exist in the native `shared/toc.c`, which is a reminder that the web extraction is an effective bug-finding tool for the original codebase. The pattern of discovering bugs in the port and back-annotating them to `NATIVE_CLI_FIXES_NEEDED.md` should become standard practice for future extractions.

The hash-set import dedup and `last_idx` file-grouping cache are micro-optimizations that won't matter at current TOC sizes, but they establish a pattern of caring about algorithmic complexity in the formatter — important when the web bridge eventually handles larger codebases. The 72KB `.wasm` binary (up from 34K before TOC) is still comfortably small for page delivery.

## Issues Encountered

### Stale `./qi` Binary Masked Current Native Behavior

- **Symptom:** `./qi zzznotreal` still printed `Pattern '...' matched 0 occurrences.` — a sentence main had removed.
- **Root Cause:** `./qi` is the repo-root build, predating the merge; the parity harness and the authoritative behavior come from the installed `qi` (current build).
- **Fix:** Switched to bare `qi` throughout; confirmed the current `query-index.c` source has no such sentence. Saved the convention to memory.
- **Regression Risk:** `NONE`
- **Follow-Up:** `NONE`

### `--debug` Exposed Two Hidden TOC SQL Divergences

- **Symptom:** `qi % -f x --toc --debug` diverged even though non-debug TOC cases matched.
- **Root Cause:** Non-debug cases never compare SQL text. Debug surfaced (a) web added `AND (symbol LIKE '%')` while native skips a bare `%` pattern, and (b) SELECT-clause whitespace differed (native's multi-literal `"  col, "` → triple spaces).
- **Fix:** Skip `%`-only patterns in the TOC branch (matches `query-index.c:3288`); reformat `build_toc_web_sql`'s SELECT literal to native spacing.
- **Regression Risk:** `LOW` — whitespace is cosmetic to SQL; the `%`-skip matches native and is a no-op filter functionally.
- **Follow-Up:** `NONE`

### File-Filter Count Counted the Wrong Thing

- **Symptom:** `qi malloc -f shared/` → native `42 files matched`, web `7`.
- **Root Cause:** The web derived its count from the main query's WHERE clause, which includes the search pattern (`malloc`). Native's `count_distinct_files` applies file/context/column filters but **not** patterns — it reports the filter's file span, not files-with-results.
- **Fix:** `emit_file_filter_count_sql` builds the count from `build_common_filters_web` (no patterns).
- **Regression Risk:** `LOW`
- **Follow-Up:** `--within` + `-f` together does not inject the within-scope into the file count (subquery form makes `injectWhereClause` unsafe) — documented, rare combo, not in the parity suite.

### `parse_int_value` Used Before Declaration

- **Symptom:** `make web` error: implicit declaration of `parse_int_value` in `print_hdr_lines`.
- **Root Cause:** `parse_int_value` is defined after `print_hdr_lines`.
- **Fix:** Added a forward declaration before `print_hdr_lines`.
- **Regression Risk:** `NONE`
- **Follow-Up:** `NONE`

## Notes / Design Decisions

- **Count round-trip without ccall signature churn:** the worker appends `KEY|N` to the build_info string and C reads it back via `find_build_line`/`parse_int_value`. This avoided touching `qi_web_format`'s signature (and the harness/pipeline callers) for the file-filter count.
- **`HDR|\x01` sentinel** positions the file-filter header between exclude and column filters (native order) without `print_hdr_lines` having to understand the other HDR lines.
- **Byte-identical debug SQL** required aligning whitespace + the `%`-skip; chosen over normalizing SQL in the comparator, so the parity check stays a true match.
- **`parity/check-parity.sh` has no build step** by deliberate request — a bad build can emit many errors at once; keeping `make web` a separate manual step lets the human act on them before testing.

## Freeform Thoughts

The single most valuable artifact this session is probably `parity/check-parity.sh` — not because the script is clever, but because the manual `node … --project sourceminder 2>&1 | grep -E '^MATCH|^DIFF'` incantation was repeated dozens of times and was exactly the kind of friction that discourages running tests often. Folding "run one command and show me the diff if it breaks" into a single invocation matches how the work actually flowed (try a command → see the divergence → fix → rebuild → re-check).

The recurring theme across #5–#10 was that main's UX rework was mostly *removals and small format tweaks* (blank lines, pluralization, a dropped sentence) that the web had faithfully mirrored in their *old* form. The web didn't have bugs so much as it had frozen an earlier native contract. Parity work here is less "fix the bug" and more "re-sync to the new contract" — which is exactly why the byte-for-byte harness is the right tool: it catches a single missing blank line that no amount of reading would reliably flag.

The `--debug` cases were the most interesting because they forced the question "how identical is identical?" — making the web's internal SQL byte-match native's is arguably over-coupling, but it's the only way the debug output can be a real parity case rather than a special-cased exception. Worth revisiting if the SQL builders drift.

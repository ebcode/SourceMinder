# Static Release Plan — "curl | sh" install

Goal: `curl -fsSL https://raw.githubusercontent.com/ebcode/SourceMinder/main/install.sh | sh`
installs all eight binaries (`index-c`, `index-go`, `index-perl`, `index-php`,
`index-python`, `index-rust`, `index-ts`, `qi`) as separate, directly-callable
commands. No merged "sm" wrapper — the multi-binary layout is a hard requirement.

## Prerequisite (DONE)

Embedded config defaults are implemented and verified: every binary carries
built-in copies of all config files (generated by `tools/embed-config.c` into
`shared/embedded_config.c` at build time), used only when no file is found on
disk. Search order: `$INDEXER_DATA_DIR` → cwd → system dir → built-ins.
`--show-config` prints the effective config and its source. This is what makes
a bare downloaded binary fully functional with nothing installed.

## Step 1: Portable static binaries

`make static` already exists for Linux (STATIC_LDFLAGS in configure:~426,
built for SWE-bench containers) — the mechanism is proven; make it portable:

- ~~configure `--portable` flag~~ **DONE 2026-07-06** — drops
  `-march=native -mtune=native` from release CFLAGS so binaries run on any
  CPU of the target architecture. Release builds use
  `./configure --enable-all --portable`. Documented in docs/RELEASE_BUILD.md.

- **Linux (x86_64, aarch64):** build in an Alpine (musl) container so binaries
  run on any distro. glibc `-static` is version-fragile; musl is not. Build
  libtree-sitter.a and libsqlite3.a from source inside the container.
- **macOS (arm64, x86_64):** fully-static is impossible (no static libSystem)
  and unnecessary — macOS ships libsqlite3.dylib. Statically link only
  libtree-sitter.a; result runs on a clean Mac.
- **Windows:** deferred to a later release (MSYS2 source build remains the path).

Per-binary static linking duplicates the tree-sitter runtime + sqlite
(~1-2 MB per binary) — accepted cost, keeps binaries independent.

## Step 2: Release build driver (release.sh + tools/release-alpine.Dockerfile)

Host-neutral (user decision 2026-07-07): no `.github/` coupling. The build
is a script anyone (dev box or any CI) runs with podman/docker; a CI
integration, if ever wanted, is a thin shim that calls `./release.sh`.

1. ~~Clone the seven grammar repos at pinned commits via `fetch-grammars.sh`~~
   **DONE 2026-07-06** — pins are the exact locally-validated SHAs; perl pins
   upstream's `release` branch (generated parser.c included, byte-identical
   to the local proven copy — no tree-sitter CLI dependency). Documented in
   docs/RELEASE_BUILD.md; README's per-language clone instructions unchanged.
2. ~~Linux builds~~ **DONE 2026-07-07** — `./release.sh` builds x86_64 and
   aarch64 static binaries in a pinned Alpine container
   (tools/release-alpine.Dockerfile: alpine 3.22, tree-sitter v0.26.8 static)
   from a clean `git archive HEAD` export. Release mode requires HEAD at an
   annotated tag `v<VERSION>` matching shared/constants.h and a clean tree;
   `--snapshot` builds commit-named test artifacts for pipeline iteration.
3. ~~Smoke tests~~ **DONE 2026-07-07** — in release.sh: every binary's
   `--version` must equal VERSION; every indexer's `--show-config` must work
   in an empty dir (embedded config); index a sample C file and query the
   symbol back with `qi`. Native-arch binaries are smoke-tested on the host
   (proves musl-static runs outside Alpine); foreign arches in-container
   via qemu.
4. ~~Package~~ **DONE 2026-07-07** — `dist/sourceminder-<version>-linux-
   <arch>.tar.gz` (eight binaries, LICENSE, README.md) + `dist/checksums.txt`.
   Where artifacts are *hosted* is a separate, open decision (see below).
5. macOS (arm64, x86_64): not covered by release.sh (needs a Mac in the
   loop); still open.

## Step 3: install.sh (repo root) — DONE 2026-07-07

`curl -fsSL https://sourceminder.org/install.sh | sh`

- Detects `uname -s` / `uname -m`; resolves the latest tag by following the
  `$BASE_URL/releases/latest` redirect (or `SOURCEMINDER_VERSION=vX.Y.Z`
  pin); downloads tarball + checksums.txt; verifies sha256; extracts the
  eight binaries to `~/.local/bin` (no sudo; `PREFIX=/usr/local` override).
- Host-neutral via the sourceminder.org URL contract (documented in the
  script header): `/install.sh`, `/releases/latest` (redirect ending in
  `/tag/<tag>`), `/releases/download/<tag>/<file>`. Decision 2026-07-07:
  sourceminder.org serves everything directly — script, tarballs,
  checksums — with no forge in the install path. (The contract matches
  GitHub's and Codeberg's release URL shape, so falling back to a forge
  behind wildcard redirects stays a five-minute change.)
- Verified against a local mock host: latest-redirect resolution, pinned
  version, installed-binary index+qi roundtrip, tampered-checksum rejection
  (exit 1).

Build order: fetch-grammars.sh → release.sh (iterate with `--snapshot`
until all platforms produce good artifacts) → install.sh last (depends on
the release asset layout and the hosting decision).

## Open decisions (host-neutrality, 2026-07-07)

Host-neutrality matters (user decision). Two GitHub assumptions remain
unresolved now that the build itself is host-neutral:

- **Artifact hosting:** where the tarballs + checksums.txt live (GitHub
  Releases was assumed; any static file host works — release.sh only
  produces `dist/`).
- **install.sh delivery URL:** raw.githubusercontent.com was assumed; needs
  a host-neutral answer (or a vanity domain from day one).

## Open decisions (RESOLVED 2026-07-06)

- First release tag: **v0.3.0-beta** (VERSION in shared/constants.h bumped
  from 0.2.1; release workflow should verify tag matches VERSION).
- Grammar pins: **exact locally-validated commits**, not latest tags (five of
  seven local checkouts were past their latest upstream tag). See
  docs/RELEASE_BUILD.md for the pin table.

## Later (out of scope for these steps)

- Homebrew tap (`brew install ebcode/tap/sourceminder`) — trivial once
  releases exist; homebrew-core requires notability.
- Windows release binaries.
- Vendoring generated grammar C sources into the repo (alternative or
  complement to fetch-grammars.sh for source builds).
